# Phase 1 `reports/` — catalog and explanations

This folder holds **structured JSON** (and a few text files) produced by Phase 1 analysis, plus **optional static knowledge-base** files used by documentation and by **Phase 3**’s `build_database.py` when present.

---

## Do we have a “report” of what Phase 1 ran?

**Yes — the run outputs are the reports.** Phase 1 does not generate a single dated PDF; it writes **machine-readable + text summaries** under `reports/`. After `python3 run_phase1.py`, use these as your **run results**:

| What you want | Open this (generated by the pipeline) |
|----------------|----------------------------------------|
| **One-page human summary of all models (structure)** | `model_analysis/summary_report.txt` |
| **Full structure, all diseases (JSON)** | `model_analysis/all_models_analysis.json` |
| **Gaps vs papers — totals across diseases** | `gap_reports/all_models_gap_summary.json` |
| **Per-disease gaps (detail)** | `gap_reports/<disease>_gap_analysis.json` |
| **Uncertainty — combined** | `uncertainty/all_models_uncertainty.json` |
| **Sensitivity (e.g. Morris)** | `sensitivity/<disease>_sensitivity_morris.json` |
| **Paper index** | `paper_collection/paper_collection.json` |

**This `REPORTS.md` file** is only a **guide** (what each folder means, how Phase 3 uses files, how to regenerate). It is **not** itself the output of a run — the JSON/txt files above are.

## 1. Generated outputs (`python3 run_phase1.py`)

Running **`run_phase1.py`** from the `phase 1` directory fills the **generated** folders below. Filenames use a slug from the model display name (e.g. `covid_19_*`, `cholera_*`).

### `model_analysis/` — Task 1.1

| File pattern | Contents |
|--------------|----------|
| `<disease>_analysis.json` | Parsed structure: compartments, flows, parameters, groups, etc., for one reference model. |
| `all_models_analysis.json` | Combined view across all models discovered in the default model directory. |
| `summary_report.txt` | Human-readable summary. |

**Purpose:** Document what is *in* each gold-standard `.compmodel` (XML-driven).

---

### `gap_reports/` — Task 2.1

| File pattern | Contents |
|--------------|----------|
| `<disease>_gap_analysis.json` | Gaps between the model and **paper promises** (from PDF text when a matching PDF is found). |
| `all_models_gap_summary.json` | Roll-up counts and severity across all models analyzed in the batch. |

**Purpose:** Support *faithfulness* checks — what the paper says vs what the encoded model contains. If no PDF is found for a disease, analysis falls back to limited generic checks.

---

### `uncertainty/` — Task 2.2

| File pattern | Contents |
|--------------|----------|
| `<disease>_uncertainty.json` | Per-parameter uncertainty notes (literature ranges, confidence flags as implemented). |
| `all_models_uncertainty.json` | **Flat list** of all parameters from all models (for aggregation). Does **not** duplicate `methodologyNotes`; read any `*_uncertainty.json` for the full per-model object including `methodologyNotes`. |

**Purpose:** Track which parameters need better literature support or calibration.

---

### `sensitivity/` — Task 2.3

| File pattern | Contents |
|--------------|----------|
| `<disease>_sensitivity_<method>.json` | Sensitivity indices / statistics (batch default is **Morris** → `*_sensitivity_morris.json`). |

**Purpose:** Screen which parameters most influence selected outputs (e.g. peak infections) under the implemented simulator.

---

### `paper_collection/` — Task 3.1

| File | Contents |
|------|----------|
| `paper_collection.json` | Index of papers associated with the reference collection (metadata used for organization and downstream indexing). |

**Task 3.1 metadata:** Entries support **`venue`** (journal/conference/book title), **`venueType`** (`journal` \| `conference` \| `book` \| `preprint` \| `other` \| `unknown`), and optional **`bibtex`** (paste from Scholar/PubMed). See `analysis/paper_collection.py` and **`../README.md`** (Validity & limitations).

**Task 2.2:** Each `*_uncertainty.json` includes a top-level **`methodologyNotes`** field explaining that outputs are **parameter-value** uncertainty and why **confidence** is often **Unknown** without literature linkage.

**Gap analysis (Task 2.1):** Promise extraction is **pattern- and/or LLM-based** — treat as an **assist**, not ground truth; for publications, compare **manual vs pattern vs LLM** on a small gold set (**`../README.md`**).

**Taxonomies / patterns (static):** Curated JSON libraries; building a **literature-backed** taxonomy is a **separate** systematic-review effort (**`../README.md`**).

## 2. Static knowledge base (not produced by `run_phase1.py`)

These paths are **expected to exist in version control** on branches that carry the AI-assisted pipeline (e.g. `compartmental`). They are **not** recreated by `run_phase1.py`. If you delete them, restore from Git (see Phase 1 **README**) or from backup.

### `protocols/`

| File | Purpose |
|------|---------|
| `extraction_protocol.json` | Rules and structure for how extraction from papers should behave in the wider framework. |
| `required_optional.json` | What model elements are treated as required vs optional for completeness checks. |

### `taxonomies/`

| File | Purpose |
|------|---------|
| `taxonomies.json` | Classification of compartment / flow / parameter types for consistent reporting. **Not** the output of an automated literature review — curation / future dedicated review work may expand this. |

### `patterns/`

| File | Purpose |
|------|---------|
| `pattern_library.json` | Reusable epidemiological modeling patterns (reference library, not per-run results). Same caveat: **curated**; automatic extraction from the literature would need its own methodology. |

### `manual_extraction/`

| File | Purpose |
|------|---------|
| `extraction_example.json` | Example filled extraction for documentation / training. |
| `extraction_template.json` | Empty or scaffold template for manual extraction workflows. |

## 3. How Phase 3 uses these files

`phase 3/build_database.py` loads Phase 1 knowledge **optionally** — each file is used **only if it exists**:

- `reports/patterns/pattern_library.json`
- `reports/taxonomies/taxonomies.json`
- `reports/protocols/required_optional.json`
- `reports/protocols/extraction_protocol.json`
- `reports/manual_extraction/extraction_example.json`
- `reports/paper_collection/paper_collection.json`
- `reports/model_analysis/all_models_analysis.json`
- `reports/uncertainty/all_models_uncertainty.json`
- `reports/gap_reports/all_models_gap_summary.json`

Missing files are skipped; the database build still proceeds with whatever is available.

## 4. Regeneration

| Goal | Command |
|------|---------|
| Regenerate **all** Phase 1 runnable outputs | `cd "phase 1" && python3 run_phase1.py` |
| Restore **static** `protocols/`, `taxonomies/`, `patterns/`, `manual_extraction/` | From Git branch that contains them (e.g. `origin/compartmental`) — see Phase 1 **README**. |

**Note:** Optional Excel/CSV exports from model analysis may require `pandas` / `openpyxl`; full sensitivity features may require `numpy` / `scipy`.
