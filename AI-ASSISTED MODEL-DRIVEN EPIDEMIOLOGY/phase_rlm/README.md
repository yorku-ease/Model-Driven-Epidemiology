# Phase RLM - Agentic Repair Loop with Self-Correction

An intelligent LLM-driven repair system for epidemiological compartmental models that uses semantic search, error memory, and iterative context gathering to fix structural errors in model XML files.

---

## Overview

Phase RLM takes a model generated by Phase 2 (LLM-generated compartmental model) and automatically repairs structural errors using:

1. **Semantic Search (FAISS)** - Finds relevant paper sections to support repairs
2. **Error Memory** - Learns from past repair attempts to improve future fixes
3. **Iterative LLM Calls** - Gathers context progressively until confident or determined unfixable
4. **Clear Decision Framework** - CAN_FIX / NEED_MORE_CONTEXT / CANNOT_FIX

## Error Types Handled

| Error Type | Severity | Description |
|------------|----------|-------------|
| `self_referential_flow` | Critical | Flow points to itself (e.g., ContactFlow target = contactCompartment) |
| `zero_population_all` | Critical | All compartments have population=0 |
| `uniform_parameter_collapse` | Critical | Multiple flows use same parameter with rate=0 |
| `missing_birth_sources` | High | Susceptible compartment lacks recruitment flow |
| `orphaned_parameters` | Medium | Parameter declared but not referenced in any flow |
| `isolated_compartment` | Medium | Compartment has no incoming or outgoing flows |

## Key Design Decisions

### 1. Full Model XML to LLM

**Problem:** Earlier versions truncated model XML to 2000 characters, causing the LLM to miss critical structural information (compartment IDs, names, existing flows).

**Solution:** Pass the **complete model XML** to the LLM so it understands the full context:
- Sees all compartment IDs (`//@compartments.0`, `//@compartments.3`, etc.)
- Understands existing flow structure
- Can make informed decisions about target compartments

### 2. LLM Returns Full Model, Not Patches

**Problem:** When LLM returns only the fixed portion, the system must intelligently merge it back into the original model. This is error-prone and ambiguous.

**Solution:** LLM returns the **complete corrected model XML**. The system validates it parses correctly and replaces the entire model.

### 3. LLM Designs Search Queries

**Problem:** Hardcoded search queries are brittle and don't adapt to specific error contexts.

**Solution:** LLM designs the semantic search query based on:
- Error type
- Error element
- Error detail
- Past repair memory

### 4. Error Memory for Learning

**Problem:** Repeating failed repair attempts wastes LLM calls.

**Solution:** Error memory stores:
- Past successes (error_type, element, fix_summary, evidence_chunk)
- Past failures (error_type, element, failure_reason)
- Uses exact match first, then semantic search for similar errors

### 5. Don't Retry CANNOT_FIX Errors

**Problem:** Re-trying errors that LLM already determined unfixable wastes iterations.

**Solution:** When LLM returns CANNOT_FIX:
- Log to error memory
- Skip in future iterations
- Focus iterations on errors that might be fixable

## Configuration

Configuration is in `configs/repair_config.json`:

```json
{
  "llm_provider": "gemini",
  "max_iterations": 5,
  "max_context_iterations": 3,
  "initial_search_k": 10,
  "additional_search_k": 5,
  "min_chunk_score": 0.25,
  "error_memory": {
    "semantic_threshold": 0.82,
    "max_results": 3,
    "min_entries_for_semantic": 10
  }
}
```

| Parameter | Default | Description |
|-----------|---------|-------------|
| `max_iterations` | 5 | Outer loop: max passes through all errors |
| `max_context_iterations` | 3 | Inner loop: max LLM calls per error |
| `initial_search_k` | 10 | Initial paper chunks to retrieve |
| `additional_search_k` | 5 | Additional chunks when NEED_MORE_CONTEXT |
| `min_chunk_score` | 0.25 | Minimum similarity score for chunks |
| `semantic_threshold` | 0.82 | Threshold for memory semantic search |
| `max_results` | 3 | Max memory entries to return |

## Usage

### Basic Usage

```bash
cd phase_rlm

# Run repair on a specific disease
python run_phase_rlm.py --disease measles --provider gemini

# Run repair on a specific report directory
python run_phase_rlm.py "../phase 2/reports/measles_llm_gemini_20260312_165901"

# Validate only (no repair)
python run_phase_rlm.py --disease measles --provider gemini --validate-only
```

### Output Files

After running, the following files are generated:

| File | Description |
|------|-------------|
| `model_repaired.compmodel` | The repaired model XML |
| `repair_report.json` | Detailed repair log with successes/failures |
| `final_validation.json` | Validation results after repair |
| `error_logs/error_log.json` | Error memory for future runs |
| `sections_vector_store/` | FAISS index for semantic search |

## Components

### StructuralValidator

Validates compartmental models for structural errors:

- Self-referential flows
- Missing birth/death flows
- Orphaned parameters
- Isolated compartments
- Population consistency

### VectorStore

FAISS-backed semantic search for paper sections:

- 500-character chunking with sentence boundaries
- SentenceTransformer embeddings
- Configurable search depth

### ErrorMemory

Stores past repair attempts for learning:

- JSON storage for entries
- FAISS for semantic similarity
- Exact match → semantic match fallback

### LLMClient

Wrapper for LLM providers:

- Supports Gemini and OpenAI
- `generate_flash()` for fast, cheap subcalls
- `generate()` for primary repair calls

## The Repair Decision Framework

LLM responses are classified into three categories:

### 1. CAN_FIX
```
Return: <CAN_FIX>complete_corrected_model_xml</CAN_FIX>
```
- Sufficient evidence from paper AND model
- Confident in the fix
- Returns full model XML

### 2. NEED_MORE_CONTEXT
```
Return: <NEED_MORE_CONTEXT>what specific information is needed</NEED_MORE_CONTEXT>
```
- Knows exactly what to search for
- System fetches more paper chunks
- LLM called again with expanded context

### 3. CANNOT_FIX
```
Return: <CANNOT_FIX>reason why unfixable</CANNOT_FIX>
```
- Evidence shows element is inherently wrong
- Data missing from paper
- Error logged, won't retry

## What Phase RLM Fixes

### Structural Fixes
- Self-referential ContactFlows
- Missing natural death flows
- Missing disease-induced death flows
- Missing recruitment (birth) flows
- Missing maturation flows

### Parameter Fixes
- Orphaned parameters linked to flows
- Expression parameters created (e.g., `e * bC`)
- Renamed/unique parameter names

### Model Completions
- External sources added
- Natural death RateFlows added to compartments
- Disease-induced death flows added

---

## What Phase RLM Cannot Fix

### Data Extraction Issues
- **Zero populations**: Paper doesn't provide initial population values
- **Missing parameter values**: Paper doesn't specify numerical rates

### Fundamental Model Problems
- Incorrect compartment structure (requires re-extraction)
- Wrong model type (SEIR vs SIR, etc.)

### Paper Limitations
- Paper doesn't contain required information
- Conflicting information in paper

## Troubleshooting

### High Failure Rate

If repairs are failing frequently:

1. **Check error memory:** Run may have previous failures cached
   ```bash
   rm -rf ../phase 2/reports/*/error_logs/
   ```

2. **Check vector store:** May need rebuilding
   ```bash
   rm -rf ../phase 2/reports/*/sections_vector_store/
   ```

3. **Check paper sections:** Ensure `paper_sections.json` exists
   ```bash
   ls ../phase 2/reports/*/paper_sections.json
   ```

### LLM Not Fixing Errors

1. **Verify full model is passed:** Check `repair_engine.py` for truncation
2. **Check prompt clarity:** Review `llm_prompts.py`
3. **Increase context iterations:** Set `max_context_iterations: 5`

### Memory Errors

1. **Clear FAISS index:** Delete `sections_vector_store/` folder
2. **Increase min_chunk_score:** Reduce false positives

### Phase RLM v1 → v2 Changes
